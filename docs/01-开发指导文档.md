# MES 连接库 · 开发指导文档

> 版本：1.0 · 目标框架：C# / .NET 10 · 面向：机器视觉检测软件与工厂 MES 系统的对接

本文件是整个类库的**总纲**。它先讲清楚“为什么这么设计”，再讲“怎么用”，最后讲“怎么扩展”。
配套文档见 [`docs/`](./) 目录下的其它文件。

---

## 1. 目标与场景

你正在开发**机器视觉检测软件**。检测软件运行在产线工位上，需要与工厂的 **MES（制造执行系统）** 双向通信：

- **查询**：开工前向 MES 要工单、配方、过站许可、序列号绑定信息。
- **上报**：检测完成后把判定结果（OK/NG）、测量值、缺陷、**检测图像**回传给 MES。
- **状态/报警**：上报设备运行状态，触发/解除报警。
- **订阅**：接收 MES 下发的指令、配方变更、报警广播。

**难点**：不同工厂的 MES 用**不同协议**（HTTP REST、MQTT、OPC UA、文件交换、数据库直连、SECS/GEM…），
字段格式、鉴权方式、数据类型也各不相同。如果每对接一个工厂就重写一遍通信代码，成本极高。

**本库的目标**：提供一套**协议无关**的统一 API。你的检测软件只依赖一个 `IMesClient` 接口，
换工厂时**只改配置、不改业务代码**即可切换底层协议。

---

## 2. 核心设计理念

| 理念 | 说明 |
| --- | --- |
| **协议无关** | 业务代码调用 `IMesClient`（如 `ReportInspectionResultAsync`），不关心底层是 REST 还是 MQTT。 |
| **可插拔 Provider** | 每种协议是一个独立 NuGet 包（`Mes.Protocols.*`），按需引用，互不依赖。 |
| **配置驱动** | 端点、鉴权、重试、图像策略、操作映射都在 `MesOptions` 里，可来自 appsettings.json。 |
| **操作目录（Operation Catalog）** | 把“业务操作”映射到“协议通道”（URL / 主题 / SQL / NodeId / SxFy），换协议即换映射。 |
| **图像双模** | 图像可**内嵌**上报，也可**单独上传**后引用，逐张可选，超阈值自动切换。 |
| **完善的事件** | 连接状态、消息、报警、上报回执、错误都有强类型事件，方便界面/日志订阅。 |
| **简单优先** | 最简用法三行代码即可跑通；高级能力按需开启。 |

## 4. 快速开始

### 4.1 最简用法（进程内回环，用于验证）

```csharp
using Mes.Core.Builder;
using Mes.Core.Models;
using Mes.Protocols.InMemory;

await using var client = MesClientBuilder.Create()
    .UseInMemory()          // 选协议：进程内回环
    .Build();

await client.ConnectAsync();

// 上报一条检测结果
await client.ReportInspectionResultAsync(new InspectionResult
{
    SerialNumber = "SN-0001",
    Outcome = InspectionOutcome.Pass
});
```

### 4.2 切换到真实工厂（只改协议行）

```csharp
// REST 工厂
var client = MesClientBuilder.Create()
    .UseRest("https://mes.factory-a.com")
    .WithAuth(a => { a.Type = MesAuthType.BearerToken; a.Token = "xxx"; })
    .Build();

// 或 MQTT 工厂
var client = MesClientBuilder.Create()
    .UseMqtt("mqtt.factory-b.com", 1883)
    .Build();

// 或文件交换工厂
var client = MesClientBuilder.Create()
    .UseFileDrop(@"\\fileserver\mes-exchange")
    .Build();
```

**业务调用代码完全不变**，只有 `UseXxx(...)` 这一行随工厂切换。

### 4.3 依赖注入用法

```csharp
services.AddMesClient(o =>
{
    o.Protocol = MesProtocolKind.Rest;
    o.Endpoint.BaseAddress = "https://mes.factory-a.com";
});
services.AddRestProtocol();   // 注册对应 Provider
```

## 5. 核心概念

### 5.1 `IMesClient` — 你唯一需要用的接口

高层、面向业务的统一 API，屏蔽协议差异。主要成员：

- 连接：`ConnectAsync` / `DisconnectAsync` / `State`
- 查询：`GetWorkOrderAsync` / `GetUnitAsync` / `GetRecipeAsync` / `GetTraceabilityAsync` / `CheckUnitPassedAsync`
- 上报：`ReportInspectionResultAsync` / `ReportMeasurementsAsync` / `UploadImageAsync` / `ReportDeviceStatusAsync` / `RaiseAlarmAsync` / `ClearAlarmAsync`
- 通用出口：`InvokeAsync<T>` / `InvokeAsync`（调用任意已映射操作）
- 订阅：`SubscribeAsync<T>` / `SubscribeAlarmsAsync`
- 事件：`ConnectionStateChanged` / `MessageReceived` / `AlarmReceived` / `InspectionReported` / `ErrorOccurred`

完整签名见 [API 参考](./04-API参考.md)。

### 5.2 `MesClientBuilder` — 流式构建器

```csharp
MesClientBuilder.Create()
    .WithName("工位1相机")
    .UseRest("https://mes...")           // 选协议（Provider 扩展方法）
    .WithAuth(a => ...)                   // 鉴权
    .WithRetry(r => r.MaxAttempts = 3)    // 重试
    .WithImageOptions(i => i.MaxEmbeddedBytes = 1_000_000) // 图像策略
    .MapOperation("GetWorkOrder", "/custom/wo/{workOrderId}", "GET") // 覆盖默认映射
    .Build();
```

### 5.3 `MesOptions` — 全部配置的载体

`Protocol` / `Endpoint` / `Auth` / `Retry` / `Tls` / `Image` / `TimeoutMs` / `DefaultHeaders` /
`DefaultParameters` / `OperationBindings` / `Properties`（协议私有键值）。可用 `Validate()` 做启动前校验。

### 5.4 操作目录（Operation Catalog）与模板引擎

**这是“配置驱动、换协议不换代码”的关键**。库内置一套业务操作键（`MesOperationKeys`）：
`GetWorkOrder`、`ReportInspection`、`UploadImage`、`RaiseAlarm` 等。

每个 Provider 都提供一份**默认映射**，把操作键映射到该协议的“通道”：

| 操作键 | REST（URL 模板） | Database（SQL 模板） | SECS/GEM（SxFy） |
| --- | --- | --- | --- |
| `GetWorkOrder` | `GET /api/mes/workorders/{workOrderId:url}` | `SELECT data FROM mes_workorder WHERE id=@workOrderId` | `S1F3` |
| `ReportInspection` | `POST /api/mes/inspections` | `INSERT INTO mes_inspection ...` | `S6F11` |

模板用 `{name}` 占位；`{name:url}` 会做 URL 编码。运行时由 `TemplateEngine` 用参数渲染。
你可以用 `MapOperation(...)` 覆盖任意一条映射以适配某工厂的特殊接口。

详见 [协议矩阵与配置](./03-协议矩阵与配置.md)。

## 6. 数据模型

面向制造/机器视觉的强类型模型（`Mes.Core.Models`）：

- **业务对象**：`WorkOrder`（工单）、`ProductUnit`（生产单元/SN）、`Recipe`（配方）、`TraceabilityRecord`（追溯）。
- **检测结果**：`InspectionResult`（含 `Measurements`、`Defects`、`Images`、`Outcome`）、
  `Measurement`（测量值 + 上下限 + 判定）、`Defect`（缺陷 + 位置 + 置信度）、`BoundingBox` / `PointF2D`。
- **图像**：`MesImage`（数据/路径/格式/传输模式/尺寸/哈希）、`ImageUploadReceipt`（上传回执）。
- **设备/报警**：`DeviceStatus`、`Alarm`（代码/描述/严重度/状态/时间）。

所有集合类字段都已初始化为空集合，可安全直接 `.Add(...)`。

## 7. 图像传输（内嵌 vs 单独上传）

每张 `MesImage` 有 `TransferMode`：

- `Embedded`：图像数据随检测结果一起提交（Base64 内嵌）。适合小图、要求单次事务。
- `SeparateUpload`：先调用上传接口把图像单独传走，拿到 `RemoteUri` 后，检测结果里只带**引用**。适合大图、对象存储。
- `ReferenceOnly`：图像已在别处，结果里只带 URI（库不再上传）。

**自动切换**：当 `Embedded` 图像大小超过 `MesImageOptions.MaxEmbeddedBytes`（默认 2MB）时，
自动改为 `SeparateUpload`，避免超大报文。逐张图像可独立设置模式 —— 满足“有些内嵌、有些单独上传，可选择”的要求。

详见 [图像传输](./05-图像传输.md)。

## 8. 事件与错误处理

- **事件**：订阅 `ConnectionStateChanged` 更新界面连接指示灯；`InspectionReported` 记录回执；
  `AlarmReceived` 弹窗；`ErrorOccurred` 落日志。
- **返回值**：所有操作返回 `MesResult` / `MesResult<T>`（`Success` / `Code` / `Message` / `Value` /
  `ElapsedMilliseconds`），**不以异常表示业务失败**，便于统一处理。
- **重试**：`MesRetryOptions`（最大次数、退避、抖动）内置于传输基类，瞬时故障自动重试。

## 9. 扩展：自定义 Provider

实现一个新协议只需两步：

1. 写 `XxxTransport : MesTransportBase`，实现 `DoConnectAsync` / `DoDisconnectAsync` /
   `DoRequestAsync` / `DoPublishAsync` / `DoSubscribeAsync`。基类已处理状态机、能力校验、事件、计时、重试。
2. 写 `XxxTransportFactory : IMesTransportFactory`（`Protocol` / `Create` / `CreateDefaultCatalog`）
   + 扩展方法 `UseXxx(...)` / `AddXxxProtocol(...)`。

即可被 `MesClientBuilder` 以完全一致的方式使用。详见 [架构设计 · 扩展点](./02-架构设计.md#扩展点)。

## 12. 常见问题（FAQ）

**Q：我完全不懂 MES，怎么开始？**
A：先运行 WPF 测试界面（InMemory 协议），把“连接→查询→上报→报警”跑通，理解数据流；再对照工厂给的接口文档，
用 `MapOperation` 调整映射即可。

**Q：工厂接口字段和库里模型对不上怎么办？**
A：三种办法：① 用 `MapOperation` 改通道；② 用 `InvokeAsync<T>` 直接传自定义 DTO；③ 覆盖操作目录。核心业务代码不受影响。

**Q：能同时对接多个工厂/多种协议吗？**
A：可以。为每个工厂各建一个 `IMesClient` 实例，用不同的 `UseXxx(...)` 即可。

**Q：图像很大（几十 MB）怎么办？**
A：设 `TransferMode = SeparateUpload`（或依赖超阈值自动切换），图像走单独上传通道，结果只带引用 URI。
