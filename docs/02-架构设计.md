# 架构设计

本文件描述 MES 连接库的分层架构、关键抽象、请求/上报/订阅的数据流，以及扩展点。

---

## 1. 分层总览

```
┌─────────────────────────────────────────────────────────────┐
│  你的应用（机器视觉检测软件 / WPF 测试界面）                  │
│  只依赖 IMesClient + MesClientBuilder                        │
└───────────────────────────┬─────────────────────────────────┘
                            │  高层业务 API（协议无关）
┌───────────────────────────▼─────────────────────────────────┐
│  Mes.Core                                                    │
│  ┌───────────────┐  ┌───────────────┐  ┌──────────────────┐ │
│  │ Client         │  │ Builder/DI     │  │ Operations        │ │
│  │ IMesClient     │  │ MesClientBuilder│ │ OperationCatalog  │ │
│  │ MesClient      │  │ MesOptions      │ │ TemplateEngine    │ │
│  └───────┬───────┘  └───────────────┘  └──────────────────┘ │
│          │  Models · Events · Common(MesResult) · Serialization│
│          │  Resilience(重试) · Diagnostics · Exceptions        │
│  ┌───────▼──────────────────────────────────────────────────┐│
│  │ Transport 抽象：IMesTransport / MesTransportBase          ││
│  │   Capabilities(Request/Publish/Subscribe) · 状态机 · 计时 ││
│  └───────┬──────────────────────────────────────────────────┘│
└──────────┼───────────────────────────────────────────────────┘
           │  实现（每种协议一个包，仅依赖 Mes.Core + 自身 SDK）
   ┌───────┴────────┬─────────┬─────────┬─────────┬─────────┬─────────┐
   ▼                ▼         ▼         ▼         ▼         ▼         ▼
 InMemory         Rest      Mqtt     FileDrop  Database   OpcUa    SecsGem
 (回环)          (HTTP)   (MQTTnet)  (落盘)   (ADO.NET) (UaClient)(Secs4Net)
```

**依赖方向永远向内**：Provider → Core，应用 → Core（+ 选用的 Provider）。Core 不知道任何具体协议。

## 2. 关键抽象

### 2.1 `IMesClient` / `MesClient`
- **职责**：把面向业务的调用（查询/上报/订阅）翻译成“操作键 + 参数 + 载荷”，交给操作目录渲染成传输请求，
  再交给传输层执行；回来后把响应反序列化成强类型 `MesResult<T>`；处理图像预处理、重试与事件派发。
- `MesClient` 是唯一实现，内部持有：`IMesTransport`、`MesOperationCatalog`、`IMesSerializer`、`MesOptions`。

### 2.2 `IMesTransport` / `MesTransportBase`
- **职责**：屏蔽“怎么把一个请求发出去”。三种能力（`MesTransportCapabilities`）：
  - `Request`：请求/响应（REST、Database、OPC UA、SECS/GEM…）
  - `Publish`：单向发布（MQTT、FileDrop…）
  - `Subscribe`：订阅接收（MQTT、SECS/GEM 主消息、FileDrop 监视…）
- `MesTransportBase` 提供**模板方法**骨架：公有 `ConnectAsync/DisconnectAsync/RequestAsync/PublishAsync/SubscribeAsync`
  负责**状态机、能力校验、计时、异常→事件、重试**；子类只实现 `DoConnectAsync` / `DoDisconnectAsync` /
  `DoRequestAsync` / `DoPublishAsync` / `DoSubscribeAsync`。

### 2.3 `IMesTransportFactory`
- **职责**：由 `MesOptions` 造出对应的 `IMesTransport`，并提供该协议的**默认操作目录**。
  成员：`MesProtocolKind Protocol`、`Create(options, loggerFactory)`、`CreateDefaultCatalog(options)`。
- `MesClientFactory` 根据 `Options.Protocol` 选中已注册的工厂来装配客户端。

### 2.4 操作目录 `MesOperationCatalog` + `TemplateEngine`
- **职责**：`操作键 → (通道模板, 动词, 是否请求响应)` 的字典。`BuildRequest(key, payload, args)`：
  用 `TemplateEngine` 渲染通道模板（`{name}`、`{name:url}`），未被模板消费的 `args` 落为查询参数/请求参数。
- 每个 Provider 用 `CreateXxxDefaults()` 给出默认映射；`MesOptions.OperationBindings` 可覆盖任意条目。

## 3. 数据流

### 3.1 请求/响应（例：`GetWorkOrderAsync("WO-1")`）
```
IMesClient.GetWorkOrderAsync
  → catalog.BuildRequest("GetWorkOrder", null, {workOrderId:"WO-1"})
      → TemplateEngine 渲染通道（REST: /api/mes/workorders/WO-1）
  → transport.RequestAsync(TransportRequest)      // 基类：状态校验+计时+重试
      → DoRequestAsync(...)                        // 子类：真正发 HTTP/SQL/…
  → 反序列化 body → MesResult<WorkOrder>
```

### 3.2 上报 + 图像（例：`ReportInspectionResultAsync`）
```
IMesClient.ReportInspectionResultAsync(result)
  → ProcessImagesAsync(result.Images)             // 逐张决定内嵌/单独上传
      → 若 SeparateUpload：先 UploadImageAsync → 拿 RemoteUri → 清空内嵌 Data
      → 若 Embedded 且超阈值：自动切 SeparateUpload
  → catalog.BuildRequest("ReportInspection", result)
  → transport.RequestAsync 或 PublishAsync（视映射 requestResponse）
  → 触发 InspectionReported 事件 → MesResult
```

### 3.3 订阅（例：`SubscribeAlarmsAsync`）
```
IMesClient.SubscribeAlarmsAsync(channel, handler)
  → transport.SubscribeAsync(channel, onMessage)  // 要求 Subscribe 能力
  → 收到 TransportMessage → 反序列化 Alarm
      → 触发 AlarmReceived 事件 + 回调 handler
  → 返回 IAsyncDisposable（释放即退订）
```

## 4. 横切能力

| 能力 | 位置 | 说明 |
| --- | --- | --- |
| 结果封装 | `Common/MesResult` | 业务失败不抛异常，统一 `Success/Code/Message/Value`。 |
| 重试 | `Resilience` + 传输基类 | `MesRetryOptions`：最大次数、退避、抖动。 |
| 序列化 | `Serialization/IMesSerializer` | 默认 System.Text.Json；可替换。 |
| 事件 | `Events` | 5 类强类型事件参数。 |
| 诊断 | `Diagnostics` | 日志/计时挂钩（`ILoggerFactory`）。 |
| 异常 | `Exceptions` | `MesConfigurationException` 等领域异常。 |
| 配置校验 | `MesOptions.Validate()` | 启动前检查端点/鉴权等必填项。 |

## 5. 扩展点

### 新增一个协议 Provider
1. 新建项目 `src/Mes.Protocols.Xxx`，引用 `Mes.Core`。
2. `XxxTransport : MesTransportBase`，设定 `Capabilities`，实现所需 `Do*` 方法。
3. `XxxTransportFactory : IMesTransportFactory`：
   - `Protocol => MesProtocolKind.Xxx`（或 `Custom`）
   - `Create(...)` 返回 `XxxTransport`
   - `CreateDefaultCatalog(...)` 返回该协议的默认操作映射
4. 扩展方法：`UseXxx(this MesClientBuilder, ...)`（独立用）+ `AddXxxProtocol(this IServiceCollection, ...)`（DI 用）。
5. （可选）在 `MesProtocolKind` 增加枚举值；在 `Directory.Packages.props` 增加第三方依赖版本。

### 替换序列化 / 重试 / 日志
- `WithSerializer(IMesSerializer)`、`WithRetry(...)`、`WithLoggerFactory(ILoggerFactory)`。

### 适配工厂私有接口
- `MapOperation(key, channelTemplate, verb, requestResponse)` 覆盖默认映射；
- 或 `InvokeAsync<T>(key, payload, args)` 直接走自定义 DTO。
