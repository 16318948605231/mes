# 打包发布与持续集成

> 本文说明如何把各库打成 **NuGet 包**、如何通过 **GitHub Actions** 实现“自动验证完成”
> （每次推送/PR 自动构建 + 测试），以及如何**发布**到 NuGet。总纲见 [开发指导文档](./01-开发指导文档.md)。

---

## 1. 本地验证（与 CI 等价）

跨平台（Linux/macOS/Windows 均可）逐项目构建 + 运行全部单元测试：

```bash
dotnet restore Mes.slnx
for proj in src/*/*.csproj; do dotnet build "$proj" -c Release; done
dotnet test tests/Mes.Core.Tests/Mes.Core.Tests.csproj -c Release
```

> 请勿在 Linux 上整体 `dotnet build Mes.slnx`：WPF 样例 `samples/Mes.TestApp` 为 `net10.0-windows`，
> 仅能在 Windows 上编译。`src/*` 全部库与跨平台样例 `samples/Mes.QuickStart`（net8.0）均可在任意平台构建。

面向真实 Broker 的集成测试默认**跳过**（视为通过），配置以下环境变量后启用：

| 变量 | 启用的测试 |
| --- | --- |
| `MES_KAFKA_BOOTSTRAP` | Kafka Provider 端到端 |
| `MES_AMQP_URI` | AMQP(RabbitMQ) Provider 端到端 |
| `MES_GRPC_URL` | gRPC Provider 端到端 |

## 2. 打包（NuGet）

打包元数据集中于 `Directory.Build.props`（版本、作者、`PackageLicenseExpression=MIT`、README、
符号包 `snupkg`、SourceLink 等），各库无需重复配置。测试/样例项目标记了 `IsPackable=false`，不会被打包。

```bash
# 打单个库
dotnet pack src/Mes.Core/Mes.Core.csproj -c Release -o artifacts

# 打全部可发布库（含聚合包 Mes）
for proj in src/*/*.csproj; do dotnet pack "$proj" -c Release -o artifacts; done
```

产物为多目标（`net8.0`、`net10.0`）的 `*.nupkg` 与对应 `*.snupkg`，内嵌 README 与 MIT 许可。

### 版本号

版本由 `Directory.Build.props` 的 `<Version>` 统一控制（当前 `1.1.0`）。发布新版本时先修改该值，
再打标签（见下）。

## 3. 持续集成（CI · 自动验证）

工作流 [`.github/workflows/ci.yml`](../.github/workflows/ci.yml) 在每次 `push` 与 `pull_request` 上自动运行：

- **`build-test`（ubuntu-latest）**：安装 .NET 8 + 10 → 逐项目构建全部库 → 运行单元测试（输出 `trx`）
  → 构建跨平台样例 → 验证可 `dotnet pack` → 上传测试结果与 NuGet 包工件。
- **`windows-full`（windows-latest）**：整体 `dotnet build Mes.slnx`（含 WPF 界面）→ 运行单元测试。

如此便实现“**自动验证完成**”：任何改动都会被自动构建并测试，结果可在仓库 **Actions** 页查看，
README 顶部的 CI 徽章实时反映主分支状态。

## 4. 发布到 NuGet

工作流 [`.github/workflows/release.yml`](../.github/workflows/release.yml) 在推送 `v*` 标签（如 `v1.1.0`）
或手动触发（`workflow_dispatch`）时运行：

1. `dotnet pack` 全部可发布库到 `artifacts/`；
2. 上传 `.nupkg` / `.snupkg` 工件（可直接下载）；
3. **若**仓库配置了密钥 `NUGET_API_KEY`，则 `dotnet nuget push ... --skip-duplicate` 推送到 nuget.org；
   未配置时跳过推送，仅产出工件。

发布步骤：

```bash
# 1. 修改 Directory.Build.props 的 <Version>，提交
# 2. 打标签并推送（触发 release 工作流）
git tag v1.1.0
git push origin v1.1.0
```

> 在仓库 **Settings → Secrets and variables → Actions** 添加 `NUGET_API_KEY` 后，标签推送即可自动发布。
